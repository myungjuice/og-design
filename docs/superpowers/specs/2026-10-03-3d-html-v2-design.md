# 3D컨셉 디자인 v2 HTML 작업 공간 설계

기존 캔버스는 보존하고, 일반 HTML 페이지에서 디자인 시스템과 앱 화면을 순차적으로 검토한다. 사용자가 검토한 `screens/my-info-3d-test/`의 3D 컨셉을 출발점으로 삼되, 기존 화면을 일괄 복사하거나 모든 화면을 동시에 렌더링하지 않는다. 이 문서는 새 작업 공간의 구조와 첫 구현 범위를 정의한다.

## 사용자와 합의한 기준

- 사이트 홈 상단에 `3D컨셉 디자인 v2` 진입 링크를 추가한다.
- 좌측 메뉴 순서는 디자인 시스템, 공통 컴포넌트, 홈화면, 마이랜드, 바코드, 오지파크, 내정보다. 공통 컴포넌트 분리와 RGB 값은 첫 단계 구현 이후 추가 승인된 기준이다. 검토 배경은 추가 피드백에 따라 연회색에서 다크 그레이로 조정한다.
- 기본 진입 화면은 디자인 시스템이다.
- 마이랜드와 오지파크는 메뉴명만 표시하는 빈 콘텐츠 화면으로 남긴다.
- 하늘색 페이지 배경과 하단 하늘색 그라디언트는 v2 기본 스타일에서 제외한다. 기존 테스트 페이지와 캔버스의 색상은 변경하지 않는다.
- 별을 새 장식으로 추가하지 않는다. 기존 테스트 페이지에서 별은 오지파크 탭 아이콘이며, 새로운 아이콘 선정은 이번 범위에 포함하지 않는다.
- 기획서에 있는 화면은 기획된 구성과 명칭을 유지한다. 기획서에 없는 화면은 기존 앱 흐름을 참고한다.
- 로컬에서 단계별로 검토하고, 배포와 푸시는 별도 승인 없이 진행하지 않는다.

## 라우트와 좌측 메뉴

새 작업 공간은 `/v2/` 아래에 둔다. `/v2/` 진입 시 `/v2/design-system/`으로 이동한다. 각 메뉴는 별도 HTML 주소를 사용하고, 좌측 메뉴의 선택 표시와 공통 레이아웃은 같은 모듈을 사용한다.

| 메뉴 | 주소 | 첫 구현 단계의 콘텐츠 |
| --- | --- | --- |
| 디자인 시스템 | `/v2/design-system/` | 기본 스타일과 재질 샘플 |
| 공통 컴포넌트 | `/v2/components/` | 3D 버튼 3종과 카드·메뉴 타일의 상태 검토 |
| 홈화면 | `/v2/home/` | 제목과 화면 연결 예정 안내 |
| 마이랜드 | `/v2/my-land/` | 메뉴명만 표시 |
| 바코드 | `/v2/barcode/` | 제목과 화면 연결 예정 안내 |
| 오지파크 | `/v2/og-park/` | 메뉴명만 표시 |
| 내정보 | `/v2/my-info/` | 제목과 화면 연결 예정 안내 |

홈화면, 바코드, 내정보의 연결 예정 안내는 첫 단계에 한정한다. 공통 컴포넌트 검토 후 실제 대표 화면으로 교체한다. 기존 테스트 페이지의 링크는 유지하여 검토 중에도 현재 시안을 볼 수 있게 한다.

주소 직접 진입, 새로고침, 브라우저 뒤로 가기가 정상 동작해야 한다. 선택한 메뉴의 HTML만 로드하며 다른 메뉴의 앱 화면 DOM을 숨겨서 함께 보관하지 않는다. 정적 HTML과 기존 ES 모듈을 사용하고 새 프레임워크를 추가하지 않는다.

PC에서는 좌측 메뉴와 우측 콘텐츠를 분리한다. 좁은 화면에서는 메뉴를 접고 접근 가능한 메뉴 버튼으로 연다. 문서와 미리보기 영역의 가로 넘침을 방지하고 키보드로 메뉴 선택과 닫기가 가능해야 한다. 검토용 메뉴는 평이한 형태로 만들고 앱 컴포넌트에 3D 표현을 집중한다.

## v2 디자인 시스템

v2 전용 토큰과 컴포넌트 외형을 새 경로 안에 둔다. 기존 `app-tokens.css`와 캔버스 컴포넌트의 값을 전역 변경하지 않는다. 기존 컴포넌트의 동작과 의미 구조를 재사용할 수 있으면 재사용하되, 3D 스타일을 화면별로 중복 정의하지 않는다.

검토 작업 공간은 눈부심을 줄인 다크 그레이이며, 제목과 설명은 밝은 색으로 표시한다. 검토용 색상은 `--v2-workspace-*`로 분리하고 앱 화면·카드·버튼의 기존 밝은 표면과 보라색 주요 액션은 유지한다. 정보·성공·주의·오류 색은 별도 의미를 유지하며, 브랜드색과 혼동시키지 않는다. 컬러별 RGB 값은 실제 앱 토큰에서 계산해 표시한다.

첫 디자인 시스템 화면은 다음 기준을 실제 HTML 샘플과 함께 보여준다.

- 컬러: 본문, 보조 본문, 표면, 주요 액션, 경계, 비활성, 상태 색의 역할.
- 타이포: Pretendard의 제목, 본문, 금액, 레이블, 캡션. 실제 제공 파일로 굵기를 구분하고 검증되지 않은 굵기 범위를 선언하지 않는다.
- 간격: 기존 4px 단위 체계를 유지하고 페이지, 카드 내부, 섹션, 목록, 인라인 간격을 구분한다.
- 곡률: 카드, 버튼, 메뉴 타일, 칩, 바텀시트의 모서리 기준.
- 재질: 평면, 얕은 홈, 약한 돌출, 주요 돌출. 빛은 좌상단에서 들어오고 하단 두께와 접촉 그림자로 깊이를 표현한다.

첫 단계의 재질 샘플은 시각 규칙 검토용이다. 완성된 상호작용 컴포넌트라고 표시하지 않는다. 버튼과 입력 등 실제 컴포넌트는 후속 단계에서 기본, 선택, 눌림, 포커스, 비활성 및 필요한 처리 상태를 검토한다.

본문과 바코드 막대에 장식 그림자나 흐림을 적용하지 않는다. 작은 상태 라벨과 입력 요소는 선명함을 유지하며, 눌림 표현 때문에 레이아웃이나 터치 영역이 바뀌지 않아야 한다. 입체 표현에 WebGL이나 3D 런타임은 사용하지 않는다.

디자인 시스템은 기본 스타일과 재질 규칙을 담당한다. 공통 컴포넌트는 좌측 두 번째 독립 메뉴로 분리하며, 버튼·카드의 실제 형태와 동작 상태를 모은다. 공통 패턴은 후속 검토 대상이다.

## 후속 화면 전환 원칙

공통 컴포넌트 검토 후 내정보, 바코드, 홈 순으로 대표 화면을 연결한다. 화면별 하위 시안은 선택 시에만 렌더링한다. 전환하지 않은 상태와 흐름을 완료되었다고 표시하지 않는다.

내정보와 바코드의 마일리지 카드는 같은 렌더 함수를 유지한다. 기본 금액, 보유 금액, 공유 적립과 선택 상태 등을 매개변수로 전달하고 별도 화면 복사본을 만들지 않는다. 현재 코드에 고정된 공유인 수와 진행바 구간은 재사용 과정에서 데이터 및 기획 의미를 대조한다.

대표 화면의 현재 기준은 홈 390×846, 바코드 390×846, 내정보 390×996이다. 이는 시안 검토용 기준 크기이며 실제 앱이 고정 높이라는 뜻은 아니다. 바코드 막대의 승인된 높이 96px와 번호부터 버튼까지 간격 16px를 유지한다. 시간, 네트워크, 배터리, OS 홈 표시선은 추가하지 않는다.

네이버 지도는 유지한다. HTML의 정적 지도 배경과 버튼 예시를 실제 지도 API, 적립, 결제 또는 인증 서비스로 연결하지 않는다. 디자이너가 제공한 에셋을 우선 사용하고, 하단 메뉴는 같은 에셋과 선택 상태 규칙으로 통일하는 것을 후속 검토 대상으로 둔다.

## 첫 구현 단계의 파일 범위

- 수정: 루트 `index.html`에 진입 링크를 추가한다. 기존 캔버스 링크와 자료 목록은 유지한다.
- 수정: `scripts/build-preview.mjs`에 `v2` 폴더의 정적 파일 복사를 추가한다. 기존 출력 경로와 파일 제외 정책은 유지한다.
- 추가: `v2/index.html`, 위 표의 7개 메뉴 HTML, 공통 메뉴 및 레이아웃 모듈, v2 토큰, 기본 스타일 및 샘플 렌더 모듈, 관련 테스트와 README.
- 변경하지 않음: 기존 캔버스, 기존 디자인 시스템 토큰 및 컴포넌트 외형, `screens/my-info-3d-test/`, 기획서 링크와 보고 자료.
- 삭제 없음. 새 패키지 설치, Figma 쓰기, 배포와 푸시 없음.

## 검증과 완료 조건

진입 링크, 7개 메뉴의 순서와 주소, 기본 진입, 새로고침, 뒤로 가기, 선택 상태를 검사한다. 마이랜드와 오지파크의 콘텐츠에 메뉴명 외의 시안을 넣지 않는다. 디자인 시스템은 검토용 재질 샘플과 실제 컴포넌트를 구분한다.

320, 375, 390, 414, 768, 1440px에서 가로 넘침, 메뉴 조작, 텍스트 겹침, 키보드 포커스를 확인한다. 글자와 버튼의 대비, 비활성 구분과 최소 터치 영역도 검증한다. v2 페이지 배경에 하늘색을 기본 적용하지 않았는지 확인한다.

빌드 결과에서 모든 메뉴에 직접 접근할 수 있어야 하며 개발 파일과 자격 증명은 제외되어야 한다. 기존 단위 테스트와 홈, 내정보, 바코드의 관련 브라우저 검증을 실행한다. 첫 구현의 완료는 새 작업 공간과 기본 스타일 검토 화면의 완료이며, 전체 화면 전환의 완료가 아니다.

검증 후 로컬 커밋을 저장하고 확인 URL과 다음 검토 대상인 버튼 및 카드 컴포넌트를 안내한다.
