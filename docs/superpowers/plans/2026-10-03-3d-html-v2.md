# 3D컨셉 디자인 v2 HTML Implementation Plan

> 첫 단계 1~3번 완료 이후 추가 승인: 검토 배경 연회색, 공통 컴포넌트 두 번째 독립 메뉴(`/v2/components/`, 총 7개), 컬러의 실제 RGB 표시. 아래 최초 계획의 6개 메뉴·흰 배경은 당시 실행 기록이며, 현재 기준은 설계 문서와 `v2/README.md`를 따른다. 4번 범위는 공통 3D 버튼·카드 상태 검토이며 대표 화면 전환은 포함하지 않는다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution or superpowers:subagent-driven-development if the user chooses delegation. Execute task by task after plan review and execution-method approval. Steps use checkboxes for tracking.

**Goal:** 사이트 홈에서 접근하는 독립 HTML 작업 공간과 3D 디자인 시스템 기본 스타일 검토 화면을 만든다.

**Architecture:** `/v2/` 아래의 정적 HTML 6개가 공통 메뉴 모듈과 v2 전용 토큰을 사용한다. 각 HTML은 자기 메뉴의 콘텐츠만 렌더링한다. 기존 캔버스와 테스트 화면의 코드 및 외형은 변경하지 않는다.

**Tech Stack:** HTML, CSS custom properties, JavaScript ES modules, Node test runner, 기존 Playwright 및 Chrome.

**Spec:** `docs/superpowers/specs/2026-10-03-3d-html-v2-design.md`

## Global Constraints

- 좌측 메뉴 순서는 디자인 시스템, 홈화면, 마이랜드, 바코드, 오지파크, 내정보다.
- 기본 진입 화면은 디자인 시스템이다.
- 마이랜드와 오지파크는 메뉴명만 표시하는 빈 콘텐츠 화면으로 남긴다.
- 하늘색 페이지 배경과 하단 하늘색 그라디언트는 v2 기본 스타일에서 제외한다. 기존 테스트 페이지와 캔버스의 색상은 변경하지 않는다.
- 별을 새 장식으로 추가하지 않는다. 새로운 아이콘 선정은 이번 범위에 포함하지 않는다.
- 첫 단계의 홈화면, 바코드, 내정보에는 제목과 연결 예정 안내만 표시한다. 대표 화면 전환은 후속 작업이다.
- 정적 HTML과 기존 ES 모듈을 사용하고 새 프레임워크를 추가하지 않는다.
- v2 전용 토큰과 컴포넌트 외형을 새 경로 안에 둔다. 기존 전역 토큰을 수정하지 않는다.
- 기본 페이지는 흰색이며, 구분이 필요한 곳에만 옅은 중립 회색을 사용한다.
- 실제 지도 API, 적립, 결제, 인증 서비스와 연결하지 않는다. OS 표시선을 추가하지 않는다.
- 삭제 없음. 새 패키지 설치, Figma 쓰기, 배포와 푸시 없음.

## Review Focus

1. 하위 주소에 직접 진입하거나 새로고침했을 때 메뉴 선택 표시와 콘텐츠가 일치해야 한다. Task 1의 브라우저 테스트로 고정한다.
2. 모바일 메뉴를 키보드로 열고 닫거나 PC 폭으로 돌아갔을 때 숨은 메뉴가 포커스를 잡거나 PC 메뉴가 사라지지 않아야 한다. Task 1에서 검사한다.
3. 글꼴 네트워크 요청 실패와 긴 한글 제목에도 콘텐츠를 읽을 수 있고 가로 넘침이 없어야 한다. Task 2에서 검사한다.
4. 밝은 입체 표면의 그림자와 액션 색 때문에 본문, 포커스, 상태 정보가 흐려지지 않아야 한다. Task 2에서 대비와 크기를 검사한다.
5. 빌드에 v2 라우트가 빠지거나 개발 파일이 공개 출력에 포함되지 않아야 한다. Task 3의 실제 빌드 검사로 고정한다.

## Task 1 메뉴와 독립 HTML 라우트

**Files:** Create `v2/index.html`, 6개 메뉴 HTML, `v2/navigation.mjs`, `v2/render.mjs`, `v2/page.mjs`, `v2/shell.css`, `v2/tokens.css`, `v2/render.test.mjs`, `v2/navigation.browser.test.cjs`. Modify `scripts/build-preview.mjs`.

**Interfaces:**

- `navigationItems`: `{id:string,label:string,href:string}[]`. ID는 `design-system`, `home`, `my-land`, `barcode`, `og-park`, `my-info`이고 순서는 Global Constraints와 같다.
- `renderSidebar({activeId:string}) -> string`: 일반 앵커와 현재 메뉴 한 개의 `aria-current="page"`를 렌더링한다.
- `renderWorkspace({pageId:string}) -> string`: 공통 메뉴와 해당 콘텐츠 한 개만 반환한다. 알려지지 않은 ID는 안전한 안내와 디자인 시스템 링크를 표시한다.
- `setupResponsiveMenu(root:HTMLElement) -> void`: 셸의 `details/summary` 메뉴를 모바일에서 접고 데스크톱에서 연다. Escape로 접고 summary로 포커스를 돌린다.
- 각 메뉴 HTML은 `body[data-page]`, `#v2-root`, 모듈 `../page.mjs`, 스타일 `../tokens.css`와 `../shell.css`를 사용한다.
- 기존 빌드 복사 대상에 `v2` 하나를 추가한다. 출력 경로와 허용 확장자 및 개발 파일 제외 정책은 유지한다.
- 브라우저 테스트는 `V2_BASE_URL`이 있으면 이를 사용하고 없으면 `http://127.0.0.1:4173`을 사용한다. Playwright는 기존 `PLAYWRIGHT_PATH`를 소비한다.

- [ ] **1. 실패할 단위 테스트를 작성한다.** 고정 메뉴의 ID, 이름, URL 순서를 독립 리터럴로 확인한다. 아래 항목도 검사한다.

```js
assert.deepEqual(navigationItems.map(x=>x.label),['디자인 시스템','홈화면','마이랜드','바코드','오지파크','내정보']);
assert.equal((renderSidebar({activeId:'barcode'}).match(/aria-current="page"/g)||[]).length,1);
assert.doesNotMatch(renderWorkspace({pageId:'my-land'}),/연결 예정/);
assert.doesNotMatch(renderWorkspace({pageId:'og-park'}),/연결 예정/);
assert.match(renderWorkspace({pageId:'home'}),/대표 화면 연결 예정/);
assert.match(renderWorkspace({pageId:'unknown'}),/디자인 시스템/);
assert.doesNotMatch(renderWorkspace({pageId:'<script>bad</script>'}),/<script>bad/);
```

- [ ] **2. `node --test v2/render.test.mjs`를 실행한다.** 아직 구현한 모듈이 없어서 실패하는지 확인한다.
- [ ] **3. 메뉴와 셸을 구현한다.** href는 `/v2/<id>/` 형식의 고정 값이다. `main`에는 해당 메뉴 제목과 콘텐츠만 표시한다. 마이랜드·오지파크는 제목 외 콘텐츠가 없다. 홈·바코드·내정보는 `대표 화면 연결 예정` 안내와 기존 테스트 페이지 링크를 둔다. 디자인 시스템 본문은 Task 2에서 연결한다.
- [ ] **4. 메뉴 브라우저 테스트를 먼저 작성한다.** 6개 주소의 직접 진입·새로고침, 링크 이동·뒤로 가기, 현재 메뉴 한 개, 마이랜드·오지파크의 `main` 텍스트가 각각 메뉴명뿐인지 검사한다. 모바일 summary Enter 열기와 Escape 닫기, 390→1440px 리사이즈 후 메뉴 표시를 검사한다. 외부 앱 화면 DOM을 숨겨서 함께 렌더링하지 않았는지도 검사한다. 빌드 복사에 v2를 추가해 첫 검증을 실행하고, 아직 모바일 동작과 외형이 없어서 실패하는지 확인한다.
- [ ] **5. 기본 토큰과 셸을 구현한다.** 기본 페이지와 표면은 흰색, 경계는 중립 회색이다. 768px 이상에서 좌측 216px 메뉴와 유동 콘텐츠, 그 미만에서는 상단 접이식 메뉴다. 현재 링크에는 색상 외 표시도 제공한다. 최소 터치 영역은 44×44px이며 포커스는 즉시 나타난다. `details`를 닫기 전에 summary로 포커스를 이동한다.
- [ ] **6. 정적 빌드와 브라우저 테스트를 실행한다.** 먼저 기존 빌드 복사 대상에 v2를 추가하고 `node scripts/build-preview.mjs`를 실행한다. 기존 미리보기 서버가 켜져 있으면 갱신된 dist를 사용하고, 꺼져 있으면 `scripts/serve-preview.py`로 루프백에서만 시작한다. 저장소 전체를 HTTP로 공개하지 않는다. 모듈 404와 pageerror가 0이어야 한다. 단위 테스트도 다시 실행한다.
- [ ] **7. Task 1 변경 파일만 로컬 커밋한다.** 메시지: `Add standalone v2 navigation workspace`. 푸시하지 않는다.

## Task 2 디자인 시스템 기본 스타일과 재질

**Files:** Create `v2/design-system/foundations.mjs`, `v2/design-system/foundations.css`, `v2/foundations.browser.test.cjs`. Modify `v2/tokens.css`, `v2/render.mjs`, `v2/design-system/index.html`, `v2/render.test.mjs`.

**Interfaces:**

- `foundationGroups`: `{id:string,title:string}[]`, ID는 `colors`, `typography`, `spacing`, `radius`, `materials`.
- `renderFoundations() -> string`: 위 다섯 그룹의 명세와 비상호작용 샘플을 반환한다. `data-foundation`으로 그룹을 식별한다.
- `renderWorkspace({pageId:'design-system'})`만 `renderFoundations()`를 소비한다. 다른 메뉴에서는 샘플 DOM이나 샘플 CSS를 로드하지 않는다.
- 토큰 역할: `--v2-page`, `--v2-surface`, `--v2-muted-surface`, `--v2-text`, `--v2-text-muted`, `--v2-action`, `--v2-on-action`, `--v2-edge`, `--v2-focus`, `--v2-error`, `--v2-success`, `--v2-warning`, `--v2-info` 및 `--v2-depth-{flat,inset,raised,primary}`.

- [ ] **1. 실패할 단위 및 브라우저 테스트를 작성한다.** 디자인 시스템 렌더 결과의 `data-foundation` 목록이 위 다섯 ID와 일치하는지, `시각 규칙 검토용` 안내가 있고 버튼·입력의 완성 상태를 주장하지 않는지 확인한다. 다른 메뉴에는 `data-foundation`이 없어야 한다. 브라우저 테스트의 기대치는 Step 5~6에 정의된 항목을 사용한다.
- [ ] **2. `node --test v2/render.test.mjs`와 기본 스타일 브라우저 테스트를 실행한다.** 그룹과 샘플이 없어서 실패하는지 확인한다. 미완성 기능 때문에 실패한 것과 테스트 환경 오류를 구분한다.
- [ ] **3. 기본 스타일 레지스트리와 렌더를 구현한다.** 페이지 제목 24/32px 700, 카드 제목 20/28px 700, 금액 28/38px 700, 본문 16/24px 400, 보조 본문 14/22px 400, 캡션 12/18px 400을 첫 검토안으로 표시한다. 간격은 4, 8, 12, 16, 20, 24, 32, 48px이고 카드 곡률 20px, 타일 16px, 버튼 12px, 칩 pill을 샘플로 보여준다.
- [ ] **4. 컬러와 재질 토큰을 구현한다.** 본문·보조 본문·보라색 액션은 현재 3D 시안의 해당 역할에서 출발한다. 페이지와 표면은 흰색, 구분 표면은 중립 회색이다. 하늘색 페이지 그라디언트는 만들지 않는다. 재질은 평면, 얕은 홈, 약한 돌출, 주요 돌출로 구분하며 좌상단 빛·하단 두께·접촉 그림자를 사용한다. 색과 그림자는 모두 v2 토큰을 참조한다.
- [ ] **5. 미리 작성한 브라우저 회귀 테스트를 실행한다.** 320, 375, 390, 414, 768, 1440px에서 루트 가로 넘침이 없고 샘플이 잘리지 않아야 한다. 흰 페이지와 중립 구분 표면의 실제 색, 글꼴 로드, 실제 400/700 선언, 금액 28/38px를 확인한다. 긴 한글 제목을 주입해 줄바꿈을 검사하고, woff2 요청을 실패시켜도 폴백 글꼴로 읽을 수 있는지 확인한다. 글꼴 실패를 의도한 케이스만 네트워크 오류 수집의 예외로 처리한다.
- [ ] **6. 대비 및 접근성 검사를 실행한다.** 작은 텍스트 4.5:1, 큰 텍스트와 포커스 3:1 이상인지 computed color와 실제 배경색으로 계산한다. 상태 색은 색 외에 이름을 함께 표시한다. 모바일 메뉴는 이전 테스트를 다시 통과해야 한다.
- [ ] **7. 실제 스크린샷을 확인한다.** 위 폭 중 390, 768, 1440px 캡처를 열어 재질 강도, 줄바꿈, 여백을 검토한다. Hallmark를 쓰되 사용자가 승인한 3D 컨셉과 흰 배경을 유지한다. 샘플을 승인 전 확정 디자인이라고 표시하지 않는다.
- [ ] **8. 단위·관련 브라우저 테스트를 재실행하고 로컬 커밋한다.** 메시지: `Add v2 foundation and material specimens`.

## Task 3 홈 진입 링크와 공개 파일 빌드 연결

**Files:** Modify `index.html`. Create `v2/build.test.mjs`, `v2/README.md`. 두 브라우저 테스트는 Task 1에서 정의한 서버 주소 계약을 사용한다.

**Interfaces:**

- Task 1에서 v2를 포함한 기존 빌드를 사용한다. 출력은 계속 `dist/`이며 허용 확장자 및 `.test.` 파일 제외 정책을 유지한다.
