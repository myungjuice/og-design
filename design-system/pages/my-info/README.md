# 내 정보 페이지

- 캔버스: /design-system/canvas/#my-info-main
- 독립 미리보기: /design-system/pages/my-info/
- 화면 원본: render.mjs / my-info.css
- 연결 화면 순서: manifest.mjs

## 현재 범위

내 정보 계열 24개 자리를 배치했습니다. 23개 페이지를 구성했고, 캐릭터 선택 1개는 보류입니다. 서비스는 이용내역과의 역할 중복을 비교할 수 있도록 검토 메모를 남겼습니다.
이 숫자는 내 정보 계열의 현재 배치 수이며 앱 전체 페이지 수가 아닙니다.
탭별 상태와 빈 상태는 이후 해당 화면 아래에 추가합니다. 문의 채널 연결은 별도 인앱 채팅 화면으로 만들지 않습니다.

기획서 슬라이드 15·17과 기존 jbmembersapp/lib/0_pages/05_my_info, 예약·웨이팅 상세를 참고했습니다.
아직 운영 범위가 정리되지 않은 OG PAY 선물·교환과 OG BOX 화면은 새로 배치하지 않았습니다.

## 재사용

메인은 avatar, surface, menuTile, sectionHeading, mileage, textButton을 조합합니다.
앱바와 하단 탭은 components/app-shell/에서 공유합니다.
surface는 className을 받아 페이지 조합용 배치 클래스를 추가합니다.
마일리지의 density: 'compact'는 좁은 요약 카드에 쓰는 공통 변형입니다.
페이지 CSS는 화면 배치와 좁은 폭 대응을 담당합니다. 컬러·폰트·그림자는 app-tokens.css를 사용합니다.

## 캔버스 원칙

동일 계열은 같은 x좌표에 세로로 배치합니다. 다른 계열은 별도 열에 추가합니다.
빈 자리는 이름·진입 경로·상태만 표시합니다. 아직 없는 UI나 동작을 미리 만들지 않습니다.
앱 화면은 inert 정적 시안입니다. 캔버스 이동과 AI 프롬프트만 동작합니다.
기존 concepts/my-info/와 PDF는 변경하지 않았습니다.

## 검토 메모

기획·기존 코드의 차이, 역할 중복, 의미가 불명확한 문구나 조건은 `design-system/canvas/review-notes.mjs`의 해당 검토 키에 기록합니다.
설정 이후 모든 페이지에는 애매한 점의 유무와 관계없이 기획 언급 여부, 기존 페이지 여부, 기존 앱 진입 경로와 코드 경로를 기록합니다. 신규 페이지는 관련 기존 기능과 구분하여 ‘신규 페이지’로 표시합니다.
각 메모에 기획서 파일명·표기 페이지·PPT 슬라이드 순서·섹션 제목을 기록합니다. 페이지 번호가 서로 다르면 둘 다 구분합니다. 기획에 없는 상세 화면은 ‘기획에 상세 없음’으로 적고 관련 상위 화면의 기획 위치와 기존 코드 경로를 남깁니다. 확인하지 않은 페이지 번호는 추정해서 쓰지 않습니다.
확인한 내용·검토할 내용·제안을 구분하고, 아직 결정되지 않은 내용을 확정처럼 쓰지 않습니다.
메모는 검토 목록과 페이지 위에 표시하며 앱 화면이나 디자인 설명에 섞지 않습니다.
메모가 있는 빈 자리도 검토 목록에 등록합니다. 사용자가 검토 완료를 눌러도 메모를 지우거나 대기로 자동 되돌리지 않습니다.
앞으로 추가·수정하는 화면도 같은 방식으로 기록합니다.
